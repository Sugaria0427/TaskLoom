# TaskLoom 当前实现与开发状态

**版本** v1.1 · **核对日期** 2026-10-25 · **产品版本** 0.2.0。

本页先列出本版实际接入能力，再区分尚待合并的工作，最后说明验收与后续顺序。本版代码纳入 PR #5 的平台调度与恢复修复，以及 PR #1 的个人请求调度、结算和两端合同整合。

## 1. 本版实际能力

| 层次 | 实际调用路径 | 当前行为 |
|---|---|---|
| L1 本地资源。 | Dispatcher → Unix socket → executor → file_stats。 | 预留工具名额、内存及产物空间，用进程与 cgroup 保护执行，按实际停止归还资源。 |
| L2 任务管理。 | ClientService → run_agent → model/tool/checkpoint。 | 推进有界文档任务，保存任务、步骤、Attempt 与成果，支持取消及核对续作。 |
| L3 个人请求。 | ClientService.model → ModelScheduler → 平台账号 API。 | 按根任务成本 DRR、期限与老化选择请求；按平台价格、硬预算余量及 Token 窗口准入，并控制在途。 |
| L4 平台请求。 | 平台 HTTP → GatewayService → SchedulingPolicy → HTTPProvider。 | 用户—根任务两级选择，原子保护账户/全局/根任务预算，按固定模型池容量派发、核对及结算。 |

当前工具仍为 `file_stats`，默认模型池使用确定性的模拟决策与用量。本机工具、进程、账户和持久账本实际运行。平台 `rr` 为默认策略，`hybrid`、`drr`、`maxmin` 作为可配置候选。

本轮已修复旧账本硬预算迁移、迟到响应覆盖结算、根任务阶段切换丢失提升欠账，以及两端把 Token 数与费用混用的问题。实现与回归入口见[两端调度修复说明](TaskLoom_两端调度修复_v1.0.md)和[平台恢复修复](TaskLoom_WP5_恢复账本修复_v1.0.md)。

## 3. 验证与实验顺序

本轮采用 WSL2 Ubuntu、Python 3.12 和锁定依赖。定向回归覆盖旧账本连续重启、乱序 UNKNOWN/FINISHED 响应、跨阶段提升债务、非默认价格、硬预算余量，以及真实 HTTP 适配器上的模型—工具—模型任务。

交付使用 `python tools/project.py verify-isolated`，在干净副本与新环境执行静态检查、单元/集成/L4 测试、构建、smoke、wheel 安装及源码外双客户端自检。对应 head 与实际结果登记在 PR #1、#5 的交付说明，本地完整日志保存于 `agent-workspace/outputs/pr-fix/20261025-pr5-pr1/`。

L4 的私有轨迹校准用例需要材料到位后执行。后续先整合多工具工作负载和资源准入，再以相同设备、模型、容量、任务与预算比较 B00、B10、B01、B11、B11+FB，记录根任务按时合格完成率、短任务尾延迟、背景最长等待和费用。
