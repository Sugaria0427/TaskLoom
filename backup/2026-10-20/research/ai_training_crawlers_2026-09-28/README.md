# AI 训练语料爬虫与网站资源损害：独立深度调研

**完成日期：2026-09-28。** 聚焦训练语料批量采集，明确排除将所有浏览器Agent、AI搜索、用户触发检索和一般DDoS混为训练爬虫。报告与材料分开存储，未改写此前选题提案，未部署或压测系统。

## 1. 最重要的结论

**问题属实，已有足够的一手材料支持立项背景。** 核心训练用途归因来自四个独立机构、三类网站：SourceHut、Codeberg、Wikimedia、MetaBrainz。站方明确归因不等于独立掌握爬虫运营者的训练流水线；其他用途不明事件只作为机制辅证。

**根因可以明确到实际工作：昂贵动态查询/生成、冷门内容回源、产物与队列的存量积累，以及分散来源合计突破单IP控制。** 严重后果包含服务中断、关键操作失败、持续性能下降、额外费用和维护/访问门槛；未证明永久数据破坏或统一的全网训练损失规模。

**现有措施并非无效。** 合作robots、挑战、缓存修复、反馈准入、成本公平和bulk数据出口已有成功。课设可验证的增量在明确资源约束下，而不在“第一次把调度用于反爬”。

**建议优先研究昂贵源站工作的预算管理，必要时扩展到生成产物生命周期。** 完美识别训练用途不是总资源保护的前提；但仅凭资源消耗也不能保证按真实人公平。具体算法和效果需实测。

## 3. 材料结构与复查

`materials/cases/` 保存机构事件原文、正文、日期、短引和案例记录；`materials/papers/` 保存论文原页、正文提取、元数据与查询响应；`materials/controls/` 保存防护与系统机制文档；`materials/crosschecks/` 保存交叉核验、反例和最新政策材料。

采集方法在 `materials/methods/`；范围协议、发现日志与总文件清单在 `materials/metadata/`；独立案例、文献和技术审查在 `materials/notes/`。提取文件均属于材料，没有混入报告目录。

核心结构化入口为 [案例记录](materials/cases/case_records.json)、[论文清单](materials/papers/papers_verified_manifest.json)、[防护来源](materials/controls/sources.json)和[文件清单](materials/metadata/artifact_inventory.json)。总清单中的哈希用于核对本地材料，不表示来源事实已经被独立复现。

## 4. 证据边界与完成状态

公开事故与产品文档已核验，关键文献的方法和限制按清单核读。SoCC2025缓存论文初次访问受阻，后由用户提供根目录PDF，现已完成全文与图表核读，见报告05。未获取任何站点私有监控或用户数据，未实施爬虫测试，未生成项目性能数据。

最终三项独立审查已记录，并在主报告修正SourceHut故障范围、ListenBrainz服务范围与Forgejo清理机制表述；技术方案补充授权、预算一致性和恢复边界。当前报告能够支持“问题存在、机制可控、实验可做”，不能支持“已证明创新或一定取得显著收益”。
