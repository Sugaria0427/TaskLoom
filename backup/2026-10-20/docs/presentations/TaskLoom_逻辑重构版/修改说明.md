## 2. 四章怎样逐级衔接

| 章节与页码 | 重组后的逻辑 | 本章给下一章提供什么 |
|---|---|---|
| 第一章，第 3—8 页 | 使用场景与公开依据 → 需求分析 R1—R4 → 对应目标 H1—H4 → 范围与已有工作。 | 确定系统必须改善的行为、验证目标与控制边界。 |
| 第二章，第 9—15 页 | 概要设计 → 工作对象模型 → 资源模型 → 两端四层架构 → 两条运行路径与落地边界。 | 明确每层管理什么、在哪里运行、以什么接口衔接。 |
| 第三章，第 16—24 页 | L1 工具准入、安全与保护 → L2 依赖、子 Agent 与结束核对 → L3 请求额度与排序 → L4 多用户公平与反馈。 | 将需求逐项落实为具有适用条件的算法和 OS 机制。 |

## 3. 内容表达与技术修正

正文增加了并发任务场景、需求表、资源分类、工具/API 双分支流程、受限容量例子、子 Agent 汇合关系、两级公平队列、反馈决策案例和开发阶段图。保留完整句子解释条件与后果，避免用算法名称或短语代替论证。

技术修正归为四组。

1. **资源与状态语义。**暂停、结果完成、实际停止和费用结算分别记录；去掉超时自动释放全部资源、SIGSTOP 等于资源归还等错误表述。旧尝试不能覆盖新结果，其真实消费仍需要结算。
2. **调度与算法边界。**修正银行家例子为 A 再得 1 个后还需 1 个；保留可控申请、可信最大需求与阶段可归还的前提。删除未定义的“慢者惩罚”，明确用户→根任务层级、成本 DRR、老化及期限排序的条件。
3. **对照与数据口径。**恢复 B11F 为 B11 加动态反馈，故障实验独立；基础安全控制在所有性能组中保留。TraceLab 只校准公开轨迹中实际存在的调用、token 和时长信息，本机资源画像需要团队实测。
4. **图文与来源。**正文运行路径区分工具和模型请求；本地取消图明确称为“取消与核对”。18 条引用采用统一编号、完整名称和可点击链接，演讲备注与当前页面同步。
