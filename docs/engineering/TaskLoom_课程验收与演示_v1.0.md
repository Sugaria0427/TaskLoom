# TaskLoom 课程验收与演示

文档版本：v1.0 · 更新日期：2026-10-28。

本指南按验收目标、真实任务、策略对照、复现检查四部分组织。演示以受控资料分析任务为代表：个人端执行 Agent 和工具，平台管理账号及共享模型请求，真实执行记录与长期仿真分别展示。

## 1. 验收目标与交付范围

| 环节 | 现场操作 | 验收依据 |
|---|---|---|
| 完整任务。 | 两个个人端分别提交文本资料，观察模型请求、工具执行和最终摘要。 | 最终文件数、词数与本地 `file_stats` 结果一致，任务成功且消费已结算。 |
| 调度与 OS 机制。 | 查看执行监控和平台控制台，调整等待任务的本地优先级。 | 任务/步骤/Attempt 可追踪，本地资源与平台额度独立计量，取消与回收事件可核对。 |
| 长期效果。 | 在对照实验页设置 7 天或 30 天、资源容量与固定种子。 | 三组使用相同工作负载；展示平均周转、P95、按时完成率和后台等待。 |
| 记录复现。 | 导出真实执行快照与实验 JSON，刷新页面恢复历史。 | 来源标签、配置、种子、模型版本、工作负载哈希和采样范围随记录保存。 |

真实任务使用实际本地工具进程、Unix socket、SQLite 账本与守护服务；具备 cgroup 委派时执行器记录实际资源指标。长期对照使用合成服务时长，复用生产策略组件，以离散事件推进模拟时间。

## 2. 启动与真实任务验收

### 2.1 选择模型模式

在项目根目录执行以下命令。Windows 入口转交已配置的 Ubuntu WSL2；Ubuntu 使用 `python3 tools/project.py`。

```powershell
python tools/project.py bootstrap
python tools/project.py dev --scenario api_constrained
```

以上使用固定模拟池。真实模型会消耗供应商额度：把 `configs/dev/upstream.example.json` 复制到仓库外，填入自己的上游密钥，并限制文件读取权限。当前机器的私有配置已经准备好，可执行：

```powershell
python tools/project.py dev --scenario api_constrained --upstream-config /home/sugaria/.config/taskloom/deepseek-private.json
```

个人端仍配置 TaskLoom 平台账号，所有模型请求经 L4；上游密钥只由平台持有。真实模式按上游 URL 与模型使用独立状态目录，避免混用模拟消费与真实用量。平台固定的是可同时发送的请求许可，模型参数与服务能力保持不变。

| 地址 | 用途 |
|---|---|
| `http://127.0.0.1:8795/` | Alice 的个人端。 |
| `http://127.0.0.1:8798/` | Bob 的个人端。 |
| `http://127.0.0.1:8796/admin` | 平台控制台；管理员密钥文件位置由启动输出给出。 |
| `http://127.0.0.1:8795/experiments` | 三策略配对仿真，独立于付费调用。 |

### 2.2 完成一轮任务

1. 在 Alice 工作台创建会话，输入一段文本或添加 UTF-8 文件，要求统计文件数、词数并生成摘要。
2. 在 Bob 工作台提交另一项任务，查看个人端请求名额和平台共享槽位的竞争。可以在队列中调整本地优先级。
3. 在执行面板检查模型与工具步骤，等待任务成功；最终统计必须与 `file_stats` 工具回执一致。真实模型可以选择不同的辅助工具，最终统计依据相同。
4. 打开“调度监控”，核对任务、预留、结算和事件，再点击“导出执行记录”。平台控制台提供账号、根任务、共享账本与调度事件视图。

输入 Token 使用 UTF-8 字节与封装余量的保守准入估计，实际 Token 由供应商回执结算。界面显示的 Token 单位用于调度和消费记录；货币费用以供应商账单为准。真实 HTTP 请求在发送后结果未知时，系统保留原身份与预留，等待人工核对消费；已确认结果继续按原 Attempt 完成结算。

### 2.3 停止服务

模拟模式使用 `python tools/project.py stop`。真实模式使用同一个私有配置路径，以定位相应状态目录：

```powershell
python tools/project.py stop --upstream-config /home/sugaria/.config/taskloom/deepseek-private.json
```

## 3. 对照实验与结果解释

### 3.1 固定工作负载与资源

打开个人端侧栏的“对照实验”，选择天数、每日任务数、用户数、每人工具/请求名额、每人内存、共享模型槽位和随机种子。默认 7 天、每天 60 项任务、种子 42–44；30 天对应每种子 1800 项任务。

| 任务类别 | 预计模型决策 / 工具 / 模型汇总时长 | 工具内存 | 完成期限 |
|---|---|---|---|
| 交互任务，约 60%。 | 1 / 1 / 2 秒。 | 64 MiB。 | 到达后 60 秒。 |
| 资料分析，约 15%。 | 4 / 8 / 10 秒。 | 128 MiB。 | 到达后 300 秒。 |
| 后台任务，约 25%。 | 8 / 35 / 60 秒。 | 384 MiB。 | 到达后 1200 秒。 |

这些参数定义受控的合成场景。实际服务时长加入 ±20% 随机波动，调度成本使用类别估计。后台集中于一名用户，在每日时段起始突发；其他任务在选定时段内分散到达。每位用户拥有独立本地资源，平台模型槽位共享。相同种子的任务、到达、服务时长和资源容量在三组中完全相同。

### 3.2 三组策略

| 策略 | 本地工具与请求 | 平台请求 |
|---|---|---|
| FIFO。 | 先到先服务，遵守相同的槽位和内存约束。 | 按到达顺序派发。 |
| 平台轮转。 | 本地 FIFO。 | 复用生产 `rr`，按用户和根任务分层轮转。 |
| TaskLoom。 | 复用成本 DRR、期限/老化与有界优先提升；可行工具可以利用剩余内存。 | 复用生产 `hybrid`，先比较占槽，再比较已获得的槽位秒。 |

三组均排空全部已到达工作，服务工作量相同。该模型研究固定服务能力下的排队与分配效果，网络失败、Token 窗口和动态反馈控制留给后续真实消融；按时完成率与真实输出质量分别评价。

### 3.3 阅读结果

页面同时呈现指标卡、完整对照表、逐日曲线和调度事件。表格为各种子的指标均值与种子间标准差；交互 P95 先在各次运行中计算，再汇总。可切换 FIFO 或平台轮转作为比较基线。

- **延迟与等待改善率**：`(基线数值 - TaskLoom 数值) / 基线数值 × 100%`。正值为改善，负值为变差；基线为零时显示不可计算。
- **按时完成改善**：报告两组完成率的百分点差。该指标使用仿真期限与完成时间。
- **每日变化**：每一天的交互平均周转时间在重复种子间取平均，便于观察结果稳定性。
- **事件与工作量**：每组展示首个种子的早期事件样本；导出包含全部种子的汇总与各组最多 360 条事件，服务工作量用于检查比较公平性。

建议先运行默认突发条件，再把到达时段改为一小时、提高模型容量，观察收益如何随竞争程度变化。报告应同时展示收益、后台等待和波动。

## 4. 复现、验收与问题定位

### 4.1 工程检查

```powershell
python tools/project.py check
python tools/project.py test unit/test_comparison.py integration/test_comparison_api.py integration/test_real_upstream.py
python tools/project.py test linux
python tools/project.py verify-isolated
```

隔离验收在新副本与新环境执行检查和测试，构建 wheel，再在源码外安装运行双账号 self-test。所有自动测试使用替身或模拟池，真实接口验收单独记录供应商回执和最终输出。

### 4.2 数据与容量

实验一次只运行一个计算，最多生成 18000 个跨种子任务。结果保留最近 12 次，重启时未完成的计算明确标记中断。真实执行快照最多导出 2000 条当前 profile 事件，文件中的 `events_truncated` 表明是否还有后续记录；完整分页采集继续使用 `tools/wp6_capture.py`。

运行状态、账号和账本位于启动输出的私有状态目录。公开仓库只保存配置模板、代码和说明；上游密钥、真实凭据、运行数据库和研究私有轨迹保留在本机。

### 4.3 常见情况

| 现象 | 处理方式 |
|---|---|
| 端口已占用。 | 先停止已有 TaskLoom 开发拓扑，或为两组个人端和平台指定独立端口。 |
| 已有账号的在途上限与场景不同。 | 使用匹配的容量场景；需要另一组场景时使用独立状态目录。 |
| 真实请求进入待核对。 | 查看原请求、上游调用及消费记录，核对后再决定续作，保留原始日志。 |
| 页面刷新后找不到旧实验。 | 检查是否使用相同 profile、模型模式及状态目录；超过 12 次的旧记录会被环形保留策略回收。 |
