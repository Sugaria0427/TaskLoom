# TaskLoom 当前实现与开发状态

**版本** v1.6 · **核对日期** 2026-10-28 · **产品版本** 0.2.0。

本文先列出当前实际能力，再说明工作包衔接，最后列出验证和后续实验顺序。本版补齐 PR #8 平台控制台、PR #9 提前取消清理、真实 HTTP 模型入口与课程对照实验，在 PR #5 平台调度与 PR #1 个人请求调度基础上，整合 PR #3 多工具运行时与恢复兼容、PR #7 本地工具资源与并发安全修复、PR #6 实验数据链和本地优先级。

## 1. 本版实际能力

| 层次 | 实际调用路径 | 当前行为 |
|---|---|---|
| L1 本地资源。 | Dispatcher → Unix socket → executor → 注册工具进程。 | 按工具画像预留名额、内存及产物空间，保存每次执行的请求与资源声明；用进程和 cgroup 保护执行，核对停止后归还资源。 |
| L2 任务管理。 | ClientService → run_agent → model/tool/checkpoint。 | 推进多轮对话与有界多工具任务，等待操作确认时不占工具资源；保存工具参数、轮次化步骤和原执行别名；支持取消、检查点升级及原身份核对续作。 |
| L3 个人请求。 | ClientService.model → ModelScheduler → 平台账号 API。 | 按根任务成本 DRR、期限、老化及有界手动优先级提升选择请求；按平台价格、硬预算余量及 Token 窗口准入，并控制在途。 |
| L4 平台请求。 | 平台 HTTP → GatewayService → SchedulingPolicy → HTTPProvider。 | 用户—根任务两级选择，原子保护账户/全局/根任务预算，按固定模型池容量派发、核对及结算。 |

Agent 支持普通多轮对话、文本与图片附件。新增 read_file 与 run_command，连同原四种附件工具共用资源画像与执行账本。普通回复直接返回自然语言；/notes 和 /stats 技能按本轮显式选择注入中文提示。统计技能使用 file_stats 核验数字，旧统计任务继续使用原协议。默认模型池使用确定性的模拟决策与用量；配置私有上游文件后，可在相同 L4 调用路径使用真实模型和本地工具。本机工具、进程、账户和持久账本实际运行。平台 `rr` 为默认策略，`hybrid`、`drr`、`maxmin` 作为可配置候选。

本轮已修复旧账本硬预算迁移、迟到响应覆盖结算、根任务阶段切换丢失提升欠账，以及两端把 Token 数与费用混用的问题。实现与回归入口见[两端调度修复说明](TaskLoom_两端调度修复_v1.0.md)和[平台恢复修复](TaskLoom_WP5_恢复账本修复_v1.0.md)。

个人端新增 `/experiments`：在独立、固定的合成任务模型中，复用生产成本 DRR、期限/老化和平台 rr/hybrid，比较 FIFO、平台轮转与 TaskLoom 组合。结果保留最近 12 次，计算为单任务准入；实际执行记录与仿真结果分别导出。详见[课程验收与演示](TaskLoom_课程验收与演示_v1.0.md)。

本轮通用 Agent 增量覆盖中文提示词、最近八轮上下文、六工具注册、图片校验、精确操作确认、有界输出、超时及进程组回收。每条本地指令与工作区外/敏感路径读取需确认；当前工作目录可在平台设置查看。详见[个人端工作台](TaskLoom_个人端工作台与验收.md)。

## 3. 验证与实验顺序

本轮采用 WSL2 Ubuntu、Python 3.12 和锁定依赖。定向回归覆盖旧账本连续重启、乱序 UNKNOWN/FINISHED 响应、跨阶段提升债务、非默认价格、硬预算余量，以及真实 HTTP 适配器上的模型—工具—模型任务。

交付使用 `python tools/project.py verify-isolated`，在干净副本与新环境执行静态检查、单元/集成/L4 测试、构建、smoke、wheel 安装及源码外双客户端自检。对应 head 与实际结果登记在 PR #1、#3、#5、#6、#7 的交付说明，此前多工具整合的完整日志保存于 `agent-workspace/outputs/pr-fix/20261025-pr3-final-review/`；本次课程闭环的验证记录保存于 `agent-workspace/outputs/development/20261028-course-demo/`，最终提交及检查结果随交付 PR 登记。

L4 的私有轨迹校准用例需要材料到位后执行。当前已贯通四工具工作负载与资源准入，后续以相同设备、模型、容量、任务与预算比较 B00、B10、B01、B11、B11+FB，记录根任务按时合格完成率、短任务尾延迟、背景最长等待和费用。
