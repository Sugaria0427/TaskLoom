# 两端调度、结算与公平记账修复

**版本** v1.0 · **日期** 2026-10-25 · **关联** WP3、WP5，PR #1、#5。

本文依次说明两端准入合同、请求结算、跨阶段公平及验收。TaskLoom 继续采用同一平台账号、固定模型池和本地受控工具。

## 1. 两端准入与公平单位

费用预算与 Token 窗口分别判断。平台通过 `admission_needs(request)` 返回费用硬上界和输入加最大输出 Token 数，个人端比较硬预算余量，平台执行最终原子准入。临时不可行请求让位给其他根任务，最早期限可唤醒等待。

ClientService 将折算后的费用上界写入 Attempt 的 `fair_charge_units`，再交给 ModelScheduler 作为公平预扣。结算沿用该原始数值，与平台回执的实际费用校正。兼容的单价为一调用仍可使用原始请求上界；新增字段默认留空，旧 Attempt 可按原请求恢复。

## 2. 终态与首次结算

执行轮询与后台核对共用客户端状态锁。保存终态时，消费、成果与结算标记在同一存储事务内提交，之后才校正内存中的公平份额。已经结算的 Attempt 遇到迟到 UNKNOWN 响应时沿用原终态，并把已确认结果交给等待中的执行路径。

平台旧账本恢复在 PR #5 中补足：未决请求保留原身份、取消意图与费用占用，重复重启保持一次预留。详见[平台恢复修复](TaskLoom_WP5_恢复账本修复_v1.0.md)。

## 3. 根任务跨阶段公平

模型请求离开队列后，根任务可能仍处于模型执行或工具阶段。CostDRR 保留提升产生的负债及后续结算差额，下一模型步骤继续偿还。未使用的正向量子在空闲时清除；根任务真正结束、队列与在途均已清空后，显式回收其结转状态。

同时修正批量派发对剩余名额的计算，使多个根任务共同使用本轮全部可用槽位。
