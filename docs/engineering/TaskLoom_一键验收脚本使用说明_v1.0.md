# TaskLoom「织序」一键验收脚本

版本：v1.0 · 日期：2026-10-28。

本文依次说明启动入口、界面场景、算法场景和结果查看。脚本用于快速准备可观察的课程演示，每次只运行所选场景；日常使用无需重复执行完整验证。

## 1. 从统一入口选择场景

在 Windows 中双击 [start.cmd](../../tools/acceptance/start.cmd)，按菜单编号选择。也可以在仓库根目录执行以下命令打开同一菜单，Windows 入口自动使用本项目的 WSL/Python 环境。

```powershell
python tools/acceptance.py
```

首次使用项目时，先按根 README 安装依赖。界面场景使用已经运行的个人端和平台，默认地址为 Alice `8795`、Bob `8798`；算法场景独立运行。

| 场景类别 | 行为与范围 |
| :--- | :--- |
| 真实界面场景 | 新建会话、发送模型请求，实际调用本地工具并打开浏览器标签页。使用当前平台配置的模型；真实上游会产生 API 消费。 |
| 独立算法场景 | 直接运行项目现有算法组件，使用可控的任务、资源或时钟，不调用模型 API。 |
| 长期策略对照 | 调用现有 `/experiments`，生成三策略配对结果并保存到个人端实验历史，不调用模型 API。 |
| 脚本自身验证 | `verify` 在临时端口和独立状态目录启动平台、个人端与免费脚本模型，集中检查关键场景。 |

脚本沿用个人端已有的耗时映射。真实并发场景只请求读取仓库文档，预设路径需要确认时自动确认该次读取；其他操作会被拒绝。脚本不读取上游密钥或 Admin Key，保持当前平台策略、资源配置和演示设置。

## 2. 真实界面场景

以下命令自动创建新的会话，并打开会话标签页及调度监控。终端同时显示本次工具运行数、等待数、共享平台占槽和任务结果。

### 2.1 三个会话读取同一份仓库文档

运行以下命令，让三个 Agent 请求读取仓库现有的 `docs/TaskLoom_项目说明书_当前完整方案.md`，并自动打开三个会话及监控页。

```powershell
python tools/acceptance.py read
```

这个场景展示多会话创建、共享文档读取、模型请求调度与执行记录。每次只返回前 4 KiB，控制模型上下文开销；已有耗时映射按源文件总字节数放大运行时长，因此现有文档已足够展示调度。

使用自己的文件时显式指定路径。相应读取内容会按正常 Agent 流程交给已配置模型。

```powershell
python tools/acceptance.py read --file "E:\Project\OS-Project\README_v1.7.md"
```

### 2.2 工具资源竞争

先在个人端设置开启已有的工具耗时映射，再运行以下命令。三个 Agent 同时读取同一份仓库文档，工具的占用时长由当前映射参数决定。

```powershell
python tools/acceptance.py tools
```

默认每人工具槽位为 2、内存预算为 512 MiB，每次读取声明 256 MiB，因此映射时间足够长时，可以观察两个工具运行、第三个等待，以及结束后的资源接替。

需要更多竞争时增加会话数量；需要更多观察时间时，使用已有界面调整映射强度。工具和模型映射可分别配置；想突出工具竞争时，可以提高工具映射时间并降低模型映射时间。

```powershell
python tools/acceptance.py tools --count 5
```

### 2.3 等待任务优先级与取消

优先级场景先让两个普通任务占用工具资源，再创建低、高优先级任务，展示不同优先级的任务共同排队。脚本核对四项优先级设置，并记录工具实际开始顺序。

生产调度采用高、普通、低 4:2:1 加权轮询，下一次机会取决于当前轮转位置；本场景展示优先级设置与排队接替，权重效果需要持续竞争才能体现。

```powershell
python tools/acceptance.py priority
```

取消场景在形成“有工具运行、有工具等待”后，取消本次创建的一个运行任务，观察实际停止和等待任务接替。耗时映射决定是否能够形成足够明显的竞争。

```powershell
python tools/acceptance.py cancel
```

### 2.4 两用户共用平台与长期比较

跨用户场景把前两项任务交给 Alice，最后一项交给 Bob。两个账号共享同一平台模型池，各自拥有独立本地工具资源。

```powershell
python tools/acceptance.py platform
```

长期比较复用现有仿真页面，运行固定种子的 FIFO、平台轮转与 TaskLoom 配对实验。结果写入现有实验历史，浏览器打开 `/experiments` 后可选择本次实验查看指标和曲线。

```powershell
python tools/acceptance.py compare --days 30
```

## 3. 独立算法场景

这些脚本调用项目真实策略组件，通过简短、确定的案例展示机制。可以单独运行，或者执行 `algorithms` 一次展示本节全部案例。

### 3.1 老化与期限提升

脚本把可控时钟推进 21 秒，展示后台任务经过老化后获得服务；随后连续放入紧急任务，展示两次提升后普通轮转仍有机会。

```powershell
python tools/acceptance.py aging
```

输出包含选中任务、提升后的成本余额和紧急竞争中的派发顺序。时间由演示时钟推进，实际运行只需片刻。

### 3.2 成本 DRR 公平

脚本让长、短请求持续竞争，单次成本分别为 1000 和 100，运行生产 `CostDRR` 并比较服务成本与派发次数。

```powershell
python tools/acceptance.py fairness
```

应观察到短请求获得更多次服务，而两方总服务成本相同；输出同时给出等次数轮转的成本对照。

### 3.3 死锁环路与有序加锁

脚本先让两项演示协程以相反顺序申请两把锁，形成真实的循环等待。0.3 秒后自动停止这组协程并释放锁，再用生产 `KeyedMutex` 的统一锁序执行相同资源组合。

```powershell
python tools/acceptance.py deadlock
```

输出展示循环等待关系与有序锁方案的完成任务。该场景只持有脚本自己创建的锁，不访问或锁住真实服务资源。

### 3.4 银行家与可行资源绕行

银行家场景使用总量为 10 的内存资源，对比贪心分配与安全性检查；释放先前分配后，再展示等待任务获得批准。

```powershell
python tools/acceptance.py banker
```

资源绕行场景复用实际 `Dispatcher`：总内存为 384 单位，一个工具持有 256，另一个 256 的工具等待，64 的小工具利用剩余空间先执行。

```powershell
python tools/acceptance.py resources
```

银行家与有序锁按独立组件展示；资源绕行使用真实调度器的内存计数和可控回调。案例中的资源单位用于表达分配关系，执行工具不会真的申请对应容量的内存。

## 4. 结果、隔离验证与清理

每次运行在 `.runtime/acceptance/<时间与随机编号>/` 保存一份 `result.json`，包括场景结果、创建的任务 ID、会话链接和必要调度采样。现场在界面看过程，在终端看关键变化即可。

结果为 `PASSED` 表示目标现象已经观察到，`NOT_OBSERVED` 表示任务完成但本轮没有形成所需竞争，`FAILED` 表示实际执行失败。真实模型的规划顺序、工具和模型映射强度都会影响竞争形态；未形成排队时，脚本保留实际观察结果并提示调整现有设置。

运行中的界面演示可以按 Ctrl+C 结束。脚本只向本次创建的未完成任务发送取消请求，保留会话和文件供复查；已提交的模型调用按平台实际回执结算。若服务中断导致取消状态无法确认，终端会给出相应会话地址，便于之后核对。

常用选项如下，每次最多创建 8 个会话，优先级场景固定为 4 个。

| 选项 | 用途 |
| :--- | :--- |
| `--no-browser` | 保留会话和终端观测，关闭自动打开浏览器标签页。 |
| `--url`、`--second-url` | 选择本机其他端口的个人端。 |
| `--count`、`--file` | 调整并发数量或读取的现有文件路径。 |
| `--timeout` | 设置单次场景等待上限，默认 180 秒。 |

修改脚本后，可用以下命令集中验证关键流程。它使用临时账号、临时端口和确定性的免费脚本模型，实际启动本地工具进程，结束后关闭自己启动的服务；当前运行的 `8795/8796/8798` 服务保持原状。

```powershell
python tools/acceptance.py verify --no-browser
```

该验证区分脚本模型的固定工具决策与真实模型的自主选择。使用真实模型演示时，如果模型没有执行预设工具，脚本会明确报出未完成并保留会话；不会把“收到一段文字回复”计为工具执行成功。
