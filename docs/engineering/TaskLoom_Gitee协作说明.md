更新日期：2026-10-15。本文依次说明主仓库与迁移范围、工作包认领、成员链接邀请及开发验收。Gitee 保存代码与协作记录，个人端和平台端的实际运行方式见根 README。

## 1. 主仓库与迁移范围

主仓库为 [Sugaria/TaskLoom](https://gitee.com/Sugaria/TaskLoom)，默认分支为 main。[GitHub 原仓库](https://github.com/Sugaria0427/TaskLoom)保留迁移前的提交和 issue，后续开发在 Gitee 进行。

迁移保留原始 Git 提交历史、全部受版本控制的文件、六个工作包 issue、对应标签及已有评论。issue 在 Gitee 使用新的平台编号，正文保留 GitHub 来源链接和原创建时间；评论保留原作者、时间与原文链接。模块标签已转换为 Gitee 可使用的名称。

本地 origin 指向 Gitee，github 远程保留原 GitHub 地址。原始论文、网页快照、运行数据、凭证、编写工作区与构建产物继续按 .gitignore 保留在本地。

## 2. 工作包认领

建议人选及模块划分见[当前完整说明书](../TaskLoom_项目说明书_当前完整方案.md)第 4.4.1 节，具体任务和验收见 [Gitee Issues](https://gitee.com/Sugaria/TaskLoom/issues)。工作包编号 WP1—WP6 保持不变，实际负责人以认领结果为准。

1. 阅读工作包的当前基础、负责边界、首批开发内容和验收清单，确认跨模块接口。
2. 在 issue 中留言认领并说明准备先交付的部分，将本人设置为负责人或由仓库管理者登记。
3. 已认领后移除“待认领”标签；协作与进度记录继续写在同一个工作包下。
4. 完成全部验收后提交结果和可复制验证方式，再关闭 issue。阶段性 PR 关联工作包并记录已完成的部分。

WP6 保留了 GitHub 用户 dailin3 的原认领留言。GitHub 账号与 Gitee 账号分别登记，仓库管理者按成员确认的 Gitee 账号设置负责人。

## 3. 通过链接邀请成员

Gitee 社区版支持按角色生成仓库邀请链接，成员打开链接并登录 Gitee 后确认加入。开启“需要管理员审核”时，成员确认后进入审核流程；关闭该选项时，成员确认后按链接所配置角色加入。

仓库拥有者按以下步骤操作：

1. 打开[仓库主页](https://gitee.com/Sugaria/TaskLoom)，进入“管理”。
2. 在“仓库设置”中进入“仓库成员管理”，选择“添加仓库成员”。
3. 选择“链接邀请”，为组员选择“开发者”角色，并设置是否需要管理员审核。
4. 将页面生成的实际邀请链接或二维码发给组员，组员登录后确认加入。

邀请链接由管理页面生成，仓库主页地址用于浏览项目。实际邀请链接仅通过团队沟通渠道分享，Git 仓库保存操作说明。

功能依据为 [Gitee 官方帮助：添加成员](https://help.gitee.com/repository/member/add)。该页面同时说明了链接邀请、直接添加和通过已有仓库邀请三种方式。

## 4. 开发与验收约定

组员先阅读根 README 和 AGENTS.md，在 Linux/WSL2、Python 3.12 环境运行现有流程。公共请求与状态契约的变更先协调调用方，再分别推进模块实现。

使用独立功能分支提交 Pull Request，描述改动目的、关联工作包、验证命令和结果，由组长或相关模块负责人评审后合并 main。个人工作包按首批交付和后续增强拆成可以独立验收的小 PR。

验证入口以 tools/project.py 和根 README 为准。改动运行定向测试；HTTP、IPC 或存储改动覆盖 integration；进程、cgroup 或守护改动覆盖 test linux；里程碑执行 verify，完整交付执行 verify-isolated。
