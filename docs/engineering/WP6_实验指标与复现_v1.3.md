# WP6 实验指标与复现

版本：v1.3 · 更新日期：2026-10-28

本工作包用同一份任务输入和质量判定比较调度条件。原始事件和任务记录来自个人端账本；容量仿真与策略仿真分别解释各自声明的实验条件。默认模型池固定容量仿真；私有上游模式可调用真实模型，个人端工具与任务账本实际运行。真实执行、机制仿真和实际输出质量分别标注来源。

## 数据流与边界

```text
固定负载 → 本地客户端与平台 → TaskState / 事件 / 资源快照
                                ↓
                         指标报告与逐任务 CSV

实测耗时和用量分布 → 30 天离散事件仿真 → 原始事件 / 汇总 / SVG 图
```

普通客户端只导出当前 profile 的任务与事件。平台公共容量通过已存在的反馈展示；本工具不跨账号收集任务，也不把平台 Key 写入导出文件。`wp6_capture.py` 对事件按序号分页，超过 100 条仍完整采集。采集结果是一次快照，任务状态和资源占用可能继续变化；正式报告应在负载结束并完成核对后采集。

## 最小混合负载与运行命令

负载定义见 [`configs/experiments/workload.json`](../../configs/experiments/workload.json)。首批四类任务按短/长期限和轻/重工具工作量组合，固定输入、预算、种子及提交顺序。本分支 Agent 支持文档统计、字面搜索、文件列表和高频词四种受控工具，质量检查仍验证完整文件数和词数。固定模型池按工具目录生成多轮工作流；实测校准保留全部轮次，禁止压缩为一次 API 调用。受控分支、代码任务和问答任务需要 WP2 提供对应工作流与可验证成果后再加入，不能用文档统计冒充。

在项目支持的 Linux/WSL2 环境中，先按所需条件启动独立状态目录的开发拓扑，再运行负载。以下是宽松参照的命令；其余三个条件将 `unconstrained` 替换为 `tool_constrained`、`api_constrained` 或 `both_constrained`。运行器会核对实际工具槽位、模型池、账户和个人请求并发容量，条件不符就退出。完整计划和每次发送意图先原子写入清单，提交失败继续记录其他任务；已受理任务仍采集结果。明确拒绝保留在成功率分母，传输中断或 5xx 标记提交未知。清单中的唯一观察编号与请求正文用于对照本地账本核对，未知提交不得盲目重发。

```bash
python3 tools/project.py dev --scenario unconstrained
python3 tools/wp6_run.py --base-url http://127.0.0.1:8795 --scenario unconstrained --seed 1 --output /tmp/wp6-run.json
python3 tools/wp6_capture.py --client http://127.0.0.1:8795 --output /tmp/wp6-snapshot.json
python3 tools/wp6_report.py /tmp/wp6-snapshot.json --run-manifest /tmp/wp6-run.json --json /tmp/wp6-report.json --csv /tmp/wp6-tasks.csv
```

每个条件需要独立 profile/状态目录以免上一组任务进入报告分母。报告命令只选择运行清单中的任务 ID，发现遗漏、重复或质量结果不完整时应失败。配对比较还须保持模型版本、输入、到达顺序、额度和质量标准一致，并记录 Git 版本、配置、机器及实际运行环境。

## 指标字典

| 指标 | 当前计算口径 | 来源与限制 |
|---|---|---|
| 按时合格完成率 | 在期限内完成、`SUCCEEDED` 且成果通过预定义质量检查的根任务数 / 本组全部提交根任务数。 | `TaskState` 创建、截止、完成时间及运行清单质量结果；失败、取消、超时和未知状态都留在分母。缺失成功任务的质量判定时不输出率。 |
| 任务 P95 | 已成功且有完整创建/完成时间的根任务历时，最近秩第 95 百分位。 | 时间从创建到完成，含排队和恢复；报告样本数须与总提交数分开。 |
| 后台最长等待 | 后台任务在各资源/额度队列的等待区间最大值。 | 现有 `TaskState` 没有后台分类和完整等待区间，当前报告标记不可用；页面显示当前阶段已持续时间，不当作历史累计等待。 |
| 服务份额 | 账号及根任务在相同观察窗口内获得的实际模型/工具服务量。 | 当前平台反馈只给账号聚合，缺少完整逐根任务服务账本，正式组间指标暂不可用。 |
| 资源与额度开销 | 工具槽位/内存预留、模型已结算单位、未结算预留分别记录。 | 预留内存、cgroup 测量的峰值内存及 CPU 秒分别报告；`consumed_units` 使用模型池计量单位。非 cgroup 运行时峰值内存和 CPU 秒保持不可用。 |
| 失败与超时 | 分别保留任务结果、超时原因和未知状态计数。 | 未完成任务不能记作成功；观察窗口结束时的未知/在途任务另列。 |

页面的“本地排队优先级”由个人端后端确认并影响本地模型/工具队列；它不代表平台共享队列优先级。取消先记录意图，实际停止、资源归还和费用结算会异步核对。页面上的当前阶段时长与资源分配来自后端事件和快照；无真实采集值时显示不可用。

## 30 天仿真与图表

`wp6_simulate.py` 使用固定种子和同一到达序列，在四种工具/API 容量条件下运行 FIFO 离散事件模型。合成夹具可使用工具—模型两阶段；实测输入必须提供完整的有序工作流，保留每一轮模型请求、工具阶段及其相关费用。输入文件必须标明 `synthetic-fixture` 或 `measured`；后者还必须给出实测来源。仓库附带的示例仅为合成夹具，不能作为 TaskLoom 性能收益证据。

短期实测完成后，可以从同一次运行的快照与清单生成实测校准输入：

```bash
python3 tools/wp6_calibrate.py --snapshot /tmp/wp6-capture.json --manifest /tmp/wp6-run.json --output /tmp/wp6-measured-calibration.json
```

校准器只接受成功且通过质量检查、消费已结算的根任务；缺失或含糊的样本会报错，不会用合成值补齐。模型服务时间取 L4 派发到完成区间，平台创建到派发的等待单独保存，不作为服务时间重放。模型费用之和必须与根任务已结算消费相等。仿真从事件队列按时间取下一就绪阶段，避免后续模型请求越过更早就绪的工作。

当前实测校准支持成功、顺序执行的受控工作流。并行依赖图或未完整采集的执行记录会明确拒绝，需要对应依赖图模拟器后再加入；服务阶段之间的调度等待由仿真重新生成。

```bash
python3 tools/wp6_simulate.py --calibration configs/experiments/synthetic_calibration.json --seed 1 --days 30 --arrivals-per-day 24 --output /tmp/wp6-simulated.json
python3 tools/wp6_plot.py --input /tmp/wp6-simulated.json --output /tmp/wp6-simulated.svg
```

保存校准输入、命令参数、原始事件 JSON、汇总 JSON 和图表 SVG，就可以重新生成同一结果。仿真只描述 FIFO 容量效应，不实现 TaskLoom 的 B00、B10、B01、B11、B11+FB 策略，也不复现 OpenClaw。真实五组对照需要 WP1 提供策略开关与统一事件、WP2 提供混合工作流、WP3/WP5 提供调度策略和份额、WP4 提供真实资源采集，再使用配对运行和实测校准。结果届时应分别标明真实执行、机制复现与模拟，并报告相对改善、重复运行波动、失败/超时及调度开销。


## 本地优先级与实验边界

用户优先级保存于根任务并影响个人端等待的模型与工具工作。模型侧复用 ModelScheduler，在期限、老化和手动提升间共享连续提升上限，提升继续扣记根任务成本；工具侧高、普通、低按 4:2:1 分配轮次，档内按根任务轮转。提升不增加平台账号份额，运行中的步骤不会因此重启。

清单中的计划任务、明确拒绝、已受理、未知发送分别可追溯；正式成功率报告要求未知状态已核对，明确拒绝仍计入分母。中断后的 `.json` 为最后完整检查点，`.tmp` 不作为有效清单。对外展示真实执行指标、固定模拟池用量和离散事件仿真结果时分别标注来源。


## 界面中的三策略配对仿真

个人端 `/experiments` 在同一个不可变工作负载上比较本地/平台 FIFO、本地 FIFO + 平台轮转、本地成本公平/期限老化 + 平台 hybrid。每个用户拥有独立的工具槽位、内存和个人模型请求名额，平台槽位共享。模型决策、工具、模型汇总依次就绪；类别提供成本估计，实际服务时长有随机波动。仿真保持服务工作量相同，排空到达任务，比较按时完成率和周转/等待指标。

页面支持 1/7/30 天和 1–5 个连续种子，展示均值与种子间标准差、逐日曲线及事件样本。改善率为 `(基线 - TaskLoom) / 基线`；按时完成率报告百分点差，负向结果保留。当前实验使用合成负载、类别估计和实际策略组件，尚未模拟网络失败、Token 窗口及反馈控制，按时完成与输出质量分别验收。该页与原 `wp6_simulate.py` 的 FIFO 容量模型保持独立。

每次计算最多生成 18000 个跨种子任务，每组保留最多 360 条最早事件样本，汇总覆盖全部任务。计算单次准入，最近 12 次结果保存在本机 SQLite 环形槽位；刷新和重启后可恢复。运行时长、随机种子、模型版本、工作负载哈希、全部种子指标及事件采样说明随结果导出。操作步骤见[课程验收与演示](TaskLoom_课程验收与演示_v1.0.md)。
