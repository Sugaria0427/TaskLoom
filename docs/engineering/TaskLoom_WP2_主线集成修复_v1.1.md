# WP2 与当前主线集成修复

版本：v1.1 · 日期：2026-10-25 · 对应 PR：#3 · 集成基线：main `e5fae41`

本文按工具目录、执行恢复、调度衔接和验收说明本轮改动。本轮完成输入版本校验修复与最终集成验收，交付到主线。

## 1. 工具目录与资源画像

保留 WP2 的工具参数校验及 grep，实现 Agent 注册目录、执行契约和处理器对 file_stats、grep、list_files、top_words 的共同支持。工具画像仍由 execution/catalog.py 管理；注册器复用画像，不再为所有工具硬编码相同需求。file_stats 验证完整语料统计，grep 的匹配词数只用于其搜索结果。

执行器统一写入 tool_name 和 arguments，工作进程兼容历史 tool 字段并拒绝相互冲突的名称。未知工具在进入进程前由契约拒绝。top_words 的参数类型和范围有明确约束。

## 2. 检查点与执行恢复

WP2 的逻辑调用描述用于验证名称和参数，WP4 的完整 ToolRun 和版本化 ToolClaim 保存实际执行合同。旧描述可以补齐；已存在的完整请求不会被升级过程缩减或按当前画像重建。

轮次化逻辑 Step 通过别名指向原 Step，原 Attempt、取消代次、CPU 参数、内存及产物预留继续沿用。回执的身份、代次、输入版本、名称或参数不一致时保持隔离占用，查询确认后再处理结果；未知执行不重复派发。

## 3. 调度与实验衔接

保留 main 的模型成本 DRR、期限、老化、手动优先级和终态结算保护，以及工具加权队列和资源恢复。完整多工具工作流被 WP6 实际采集、费用对账和事件仿真保留。工具运行器与核对器共用终态锁和结算标记，首次完成才发布终态事件，避免重复完成记录使校准产生歧义。默认模拟模型池覆盖整个工具目录，启动自检依据当前目录验收每一工具及其依赖。

## 4. 验收与文档

回归覆盖同一调用 ID 跨轮次复用、名称和参数冲突、旧检查点备份、完整 ToolRun 与历史资源声明兼容、执行器回执冲突、四工具真实执行、采集校准闭环，以及 Linux 取消和 cgroup 回收。head 与命令、结果登记在 PR 描述。

README、当前实现和基础架构更新至 v1.4，WP6 复现说明更新至 v1.2；旧件、贡献者原 README 及 SHA-256 清单保存在 `backup/2026-10-25/document-revisions/wp2-integration/`。


## 最终复审补充

旧格式 Attempt 只保存工具名称和参数。此前该分支的回执校验未检查输入版本，启动核对阶段可能将另一批输入的已完成结果标为本任务成功；即使文件数、词数相同，语料内容也可能不同。

当前统一在所有回执格式分支前校验根任务输入版本，拒绝错误版本并保留原预留。回归先提供名称、参数和统计数量均相同、输入版本不同的成功回执，确认任务保持 UNKNOWN 且不发起后续模型请求；随后提供正确回执，确认原 Attempt 可以恢复并完成，工具不重复执行。
