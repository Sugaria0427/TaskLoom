## 1. 当前可运行的能力

个人端在 Linux/WSL2 上执行受控任务，浏览器提供操作界面；平台注册账号、统一分配额度，并连接一个固定容量的模拟模型池。开发命令启动 Alice、Bob 两套隔离个人端。

| 层次 | 当前已接入的运行路径 | 能观察到的事实 |
|---|---|---|
| L1 本地资源。 | `client/dispatcher.py` 预留资源，经 Unix socket 调用 executor，真实执行 `file_stats`，用进程组和 cgroup 保护工具。 | 工具许可、内存预留、输出与产物、停止及资源归还。 |
| L2 任务管理。 | `client/service.py` 与 `runtime/agent.py` 推进有界文档统计流程，保存 Task、Step、Attempt、输入版本及成果。 | 多任务、取消与核对续作、会话归档、持久状态及恢复事件。 |
| L3 个人请求。 | 本机按根任务基础轮转；所有模型请求经平台注册账号 Key 发送到 L4，结合个人预算和基础反馈等待。 | 本地请求队列、在途许可、任务消费、平台等待提示。 |
| L4 平台请求。 | 按用户及根任务基础轮转；原子更新账户和全局账本后派发至模拟池，按原请求核对未知结果。 | 用户/全局额度、队列、模拟池在途与峰值、幂等结算。 |

当前实际工具只有 `file_stats`。每条会话消息建立独立文档统计根任务；会话用于组织记录。成本 DRR、手动任务优先级、子 Agent 扇出、阶段银行家与自适应反馈列入后续开发。

模型池通过端口与 HTTP 适配器隔离。真实模型服务需要实现并验证兼容的请求、用量与未知结果核对协议，当前默认运行使用模拟池；接入工作归 WP1，与算法实验分别验收。

## 3. 后续开发与交付顺序

先扩大可验收工作负载，再比较算法收益。每一步保留现有可运行基线与硬约束。

| 阶段 | 主要工作 | 进入下一阶段的证据 |
|---|---|---|
| 受控多工具。 | 完成 WP2 修复，统一工具注册、参数、调用身份、输入版本与最终成果验收。 | 真实多步任务、失败路径、取消及工具消费链集成测试。 |
| 请求公平与资源准入。 | 修复并接入 WP3，测量 WP4 工具画像；WP5 在同一身份/单位协议下扩展平台公平。 | 异质成本、持续竞争、并发利用和账本不变量测试。 |
| 子 Agent 与联合实验。 | 分支继承根任务份额，增加受控阶段安全检查、期限/老化与反馈消融。 | 同负载比较 B00、B10、B01、B11、B11+FB，并验收完整任务质量。 |
| 真实产品对照。 | 固定 OpenClaw 版本与合理配置，使用可比任务、工具、模型和预算；必要时另做兼容接入。 | 真实产品对照与同底座策略消融分别记录，保留原始轨迹与成本。 |

OpenClaw 的原版产品对照属于首版实验，完整兼容插件作为后续扩展。主线是自研轻量运行时和调度核心。
