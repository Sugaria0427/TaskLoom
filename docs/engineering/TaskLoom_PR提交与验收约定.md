# TaskLoom PR 提交与验收约定

更新日期：2026-10-20。本文按范围、契约、验证和修订四步组织交付，供成员从工作包 issue 提交可独立评审的增量。长期工程规则见 [AGENTS.md](../../AGENTS.md)，提交正文采用 [Gitee PR 模板](../../.gitee/PULL_REQUEST_TEMPLATE.md)。

## 1. 明确范围与实际接线

PR 关联 WP1—WP6 的工作包，写清本次完成的行为、调用入口和依赖模块。以用户提交任务为起点，说明改动经过哪些运行时、调度、工具或平台接口，最后如何交付成果和结算消费。

组件基础也可以单独提交。提交正文应明确“组件基础”及其接入条件，给出调用方、约定接口和后续工作包；当前能力文档按真实调用链更新。涉及多个工作包时，由接口双方核对后再合并。

主线是自研轻量 TaskLoom Agent 运行时。OpenClaw 原版对照服务于实验，兼容接入按明确的适配目标独立交付。

## 2. 核对跨模块契约

修改契约时同时检查生产者、消费者、测试替身和文档，重点核对以下四组信息。

| 信息组 | 必须明确的内容 | 对应的失败处理 |
|---|---|---|
| 能力与参数。 | 工具名称、参数结构、可选值、输入版本、最终成果来源。 | 未知工具及非法参数返回稳定错误；模型输出进入执行前校验。 |
| 数量与单位。 | 工具清单上限、正文大小、成本单位、预算/速率/在途的不同含义。 | 超总容量或永久耗尽明确拒绝；可恢复不足记录恢复条件。 |
| 身份与代次。 | 用户、根任务、Step、Attempt、request_id、取消代次和工具调用身份。 | 重复传输核对原请求；新执行建立新尝试；旧结果按原归属处理。 |
| 状态与终态。 | 队列、派发、完成、未知、过期、取消和待核对的转换及拥有者。 | 每次入队最终获得结果、明确错误或可追踪的未知状态；异常后核对占用。 |

例如，工具注册数量应与模型请求契约一致；测试替身应使用平台实际定义的状态。当前网关请求状态为 `QUEUED`、`DISPATCH_INTENT`、`FINISHED`、`UNKNOWN`，任务和工具状态另按各自契约处理。

## 3. 验证行为与工程检查

### 3.1 从不变量设计测试

测试以任务完成、服务份额和失败收敛为判据。涉及调度与生命周期时，按改动覆盖以下四类行为。

| 行为 | 必须观察的结果 |
|---|---|
| 公平与活性。 | 长短请求、不同成本及分支数下的服务量符合声明；持续竞争中后台和大请求仍有推进机会。 |
| 并发与利用。 | 有两个可用许可和两个可行请求时，慢响应仍允许另一请求进入；反馈等待或不可行队首保留其他派发机会。 |
| 异常与终止。 | 反馈故障、回调失败、取消、超时、过期和预算耗尽后，调用者得到可核对状态，许可与预留按事实收敛。 |
| 真实消费边界。 | 至少一条链路由真实生产者生成输入，通过真实消费者完成；使用相同名称、参数、身份和终态。 |

成本公平按成本单位比较服务量，同时报告观察时长、饱和条件、权重和未完成工作。只检查函数返回顺序不足以证明公平；仅检查并发没有超过上限也不足以证明并发可用。

### 3.2 使用统一验证入口

命令由 `tools/project.py` 定义，运行方式与环境见[根 README](../../README.md#4-验证与继续开发)。

| 变化范围 | 必需验证 |
|---|---|
| 局部策略或领域规则。 | 定向行为测试与 `check`；里程碑执行 `verify`。 |
| HTTP、IPC、配置契约或存储。 | 定向测试和 `test integration`，核对实际调用方。 |
| 进程、cgroup、取消回收或守护。 | 相关进程测试及 `test linux`。 |
| 完整交付。 | `verify-isolated` 验证干净副本、锁定安装、构建与源码外运行；涉及界面再记录浏览器验收。 |

聚合命令因前置失败停止时，分别记录已执行、失败和未执行阶段。单独通过 lint 或类型检查，记录其各自结果。

## 4. 记录提交、审查与修订

PR 写明验证 head、环境、完整命令与结果；证据包含成功数量、失败原因及尚未执行内容。最后一次代码变更后重跑受影响检查，并保证记录对应最终代码。

修订逐项关联审查意见、处理方式和回归场景。新建累计或替代 PR 时，标明继承的提交与旧 PR，承接尚未解决的意见；由维护者关闭被替代 PR，保留审查历史。合并前核对依赖已满足、文档状态已同步，验证分支与待合并 head 一致。

本约定吸收了 WP2 多工具与 WP3 调度提交的共同问题：跨模块契约、真实接线、行为测试和验证证据。具体缺陷与复现保留在各自 PR，长期规则维护在根 AGENTS。
