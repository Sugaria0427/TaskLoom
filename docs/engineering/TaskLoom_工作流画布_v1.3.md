# TaskLoom 工作流画布

文档版本：v1.3 · 更新日期：2026-10-28。

本文依次说明画布的使用、任务保留规则、流程建模与调度信息，以及本轮验证。
该版本将原“调度树”改为多个 workflow 共用的自由画布。

## 1. 使用方式

在个人工作台右侧选择 **Workflows** 页签，与“执行与资源”切换。
画布以根任务为单位展示流程，外框标明所属对话；多个任务在同一坐标空间内分区排列。

| 操作 | 作用 |
|---|---|
| 拖动画布空白区域。 | 平移查看其他任务与步骤。拖动从背景开始，节点保持点击查看详情。 |
| 滚轮、双指捏合或加减按钮。 | 缩放画布。滚轮以指针位置为中心，缩放范围为 10%—250%。 |
| 点击节点。 | 查看任务归属、执行状态、资源申请、等待原因、依赖与时间。 |
| 会话管理、定位活跃、适应全图。 | 下拉列表每行显示会话名称、活跃状态与展示状态，行末按钮可直接加入或移出画布；选中后可定位和重命名。定位活跃与适应全图继续作用于当前画布。 |
| 展开画布。 | 在更大的浮层中查看同一画布；再次点击或按 Escape 收起。 |

画布获得键盘焦点后，方向键平移，加减键缩放，0 键适应全图。
节点可以通过 Tab 聚焦和 Enter 激活。节点详细信息可跳转到所属对话。
数据每秒随原有接口刷新；节点身份、当前选择、平移和缩放保持稳定。
右侧栏左边缘可拖动调整宽度，双击恢复默认值；宽度在浏览器中保存。

会话列表优先排列活跃会话，并分别标明“活跃／已结束／暂无任务”和“已展示／未展示”。
点击会话名称只选中会话；点击独立的“定位”按钮才移动画布。
行末加入或移出按钮保持列表展开，不改变当前缩放和平移。

会话展示选择按平台与账号保存到浏览器。移出会话会隐藏其全部 workflow，正在执行的任务继续运行。
加入历史会话时，优先展示该会话最近的一项任务，再按原规则补足历史展示位。
已有至少 5 项可见活跃任务时，历史会话的加入按钮提示容量条件；用户可先移出部分会话。

重命名使用现有会话更新接口，保存后同步左侧列表、下拉栏与画布外框。
重命名对象固定为打开编辑框时选中的会话，与聊天区当前打开哪个会话相互独立。

## 2. 任务保留规则

保留数量按根任务计算，每个根任务形成一条 workflow。下述自动规则应用于未被用户手动移出的会话。
可见活跃任务统一排在画布前部，非活跃任务排在后部；两组内部保持原有相对顺序。
任务状态变化时更新分组，画布镜头保持用户当前的缩放和平移。

- **自动展示保留全部活跃任务。** 包括 PENDING、UNKNOWN 以及仍未确认资源静止的任务。
- **历史任务补足 5 条。** 活跃任务不足 5 条时，按完成时间从新到旧选择已结束任务；活跃任务达到或超过 5 条时，只展示全部活跃任务。
- **淘汰仅影响画布。** 新任务加入后，超出展示数量的最老非活跃任务退出画布，原任务、对话、日志与消费记录仍保留在原存储中。

例如：2 项活跃任务和 8 项历史任务，展示 2 项活跃与最近的 3 项历史；
8 项活跃任务同时运行时，画布展示全部 8 项。

## 3. 流程模型与调度信息

### 3.1 实际依赖

根任务节点连接任务入口。实际步骤按照 Attempt 已保存的前置依赖进行拓扑分层：
模型决定多个工具时，工具并行排列；后续步骤依赖多个工具时，连线汇合到后续步骤。
实线表示已记录的步骤依赖，入口虚线表示根任务与入口步骤的归属。
旧记录缺失的依赖保持缺失，循环或缺失前置引用在详情中标为待核对。

画布只追加 Agent 已揭示的步骤。每个步骤选取根任务当前映射的 Attempt，重试后由新的当前 Attempt 替换显示。
子 Agent 扇出继续沿项目的后续实现计划推进，当前画布展示已实现的根任务、模型和工具步骤。

### 3.2 状态、资源与时间

节点用文字和颜色区分执行、等待、完成、失败与待核对状态。
详情包含模型成本 DRR 的估计成本与轮转余额、工具名额与内存声明，以及具体资源缺口。
模型与工具队列沿用真实调度器的观察数据。

步骤时间包含建立、本地派发和结果结算；平台回执包含平台入队、派发与完成时间。
模型的本地派发表示请求已提交平台，其后时长包含平台排队与上游调用。
工具数值展示调度预算和预留。旧记录缺失的时间显示“未记录”。

### 3.3 预计下一项

半透明蓝色虚线卡片表示对应已揭示步骤的候选派发预览；点击可查看选择原因与成立条件。
它与同一 Attempt 关联，表示该步骤可能成为队列下一次选择。

模型队列在复制的 DRR、期限、老化与优先级状态上执行只读选择。
工具队列按当前加权轮转与资源可行性预览，当前资源不足时写明“全部本地资源释放”的条件。
两种队列资源独立，可以同时存在候选。
平台反馈缺失、过期或客户端连接中断时隐藏候选，保留已知执行流程。
候选随新请求、取消、优先级调整和资源变化更新。

## 4. 实现与验证

`workflow-model.js` 负责保留规则、数据投影与依赖布局；`scheduler-tree.js` 负责画布交互、节点与详情。
布局采用两列 workflow 分区，每条流程内部按依赖分层，同级节点超过三列时换行。
DOM 节点以稳定身份复用，SVG 绘制依赖与候选连线，平移缩放只改变统一世界坐标变换。
本轮继续使用已有 `GET /api/v1/resources` 数据，无新增后台任务或付费 API 调用。

参考本机 DSH 插件 `dsh-better-sidebar@0.28.0` 的数据与布局分离、背景拖动、指针中心缩放和视角保持方式，
按 TaskLoom 的根任务与实际依赖独立实现；插件源文件保持原样。

关键验证命令：

```powershell
node tests/web/test_workflow_model.cjs
node --check src/taskloom/web/scheduler-tree.js
python tools/project.py test integration/test_scheduling_observation.py
```

数据验证覆盖任务保留与淘汰、超过 5 项活跃任务、会话隐藏与优先加入、并行分支与汇合、循环依赖、断连隐藏候选及节点不重叠。
浏览器使用实际历史数据与隔离页面内的受控状态检查缩放、背景拖动、节点详情、视角保持、展开收起与窄屏排版。
会话管理已在独立临时拓扑验证加入与移出后的刷新记忆，以及重命名经真实接口保存并同步三个展示位置。
本轮通过浏览器内受控状态验证活跃排序、行内按钮、活跃但未展示标识、选择保持视角、定位移动视角，以及加入和移出保持菜单展开。
调度器原有只读预览与时间持久化验证继续复用。
