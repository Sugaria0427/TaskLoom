# WP4 恢复与并发安全修复

版本：v1.0 · 日期：2026-10-25 · 对应 PR：#7

本文依次说明执行恢复、动态声明、取消安全和当前接线范围。

## 1. 执行身份与资源预留

每个工具 Attempt 在派发前保存完整 ToolRun 和带版本的 ToolClaim，保存槽位、内存与产物预算。恢复时复用这次执行的声明，不再采用整个工具目录的最大资源向量。原预留占满容量时，同一执行身份仍可进入核对路径，确认停止后释放资源。

旧记录优先使用执行器保存的请求回执补齐契约。缺少回执的历史记录根据待执行工具补齐，最早仅有 file_stats 的记录沿用其 128 MiB 内存和 3 MiB 产物预算。已派发但未取得结果的执行只查询原身份；没有回执时保留预留并等待核对。

声明冲突返回稳定错误，保留未知执行的原预留，调度循环继续处理其他可执行请求。

## 2. 阶段银行家检查

动态修改最大需求时，先对候选最大需求与当前分配联合计算安全序列；存在安全序列才提交修改。拒绝保留旧声明、旧分配和拒绝原因。显式关闭安全检查的贪心模式仍作为对照。

## 3. 取消与共享操作

多锁获取遇到取消或异常时，逆序释放已经取得的锁；重复键去重。SingleFlight 用屏蔽取消的等待方式隔离调用者，任一等待者取消不影响共享操作。组件持有共享任务直到结束，限制同时执行的键数量，并通过 close 显式取消、回收其拥有的工作。

## 4. 实际接线与验证

工具资源画像、进程执行、cgroup 参数和测量值进入当前本地执行路径。银行家、读写锁、命名互斥锁及 SingleFlight 是已测试的可复用基础组件；生产工具尚未依赖这些组件。多工具 Agent 目录接入由 WP2 衔接。

定向测试覆盖最小内存预算恢复、原身份查询、预留冲突隔离、动态 Max 拒绝、取消回滚及共享任务存活。交付证据由 PR 描述列明验证 head、Linux 进程检查和隔离安装验收。
