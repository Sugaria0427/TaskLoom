# WP5 旧账本恢复与预算保护

**版本** v1.0 · **日期** 2026-10-25 · **关联** PR #5、WP5 平台请求调度。

本文说明旧账本的恢复缺口、迁移过程和回归验收。模型服务池容量及默认轮询策略保持现有配置。

## 1. 问题与修复

旧版本只保存预计预留，新版硬预算改用 `worst_units`。旧请求尚未核对时，这一新增字段原先按零恢复，会让预算为 100 的平台继续派发两项各需 70 的工作。

启动恢复现在为每项未决请求补足预算上界与窗口预留，并按未决请求身份重建账户及全局预留、硬预算占用和在途数。原请求身份、取消意图和实际消费保留。已有硬预算值继续沿用，避免重新定价已派发工作。

## 2. 原子恢复与重复启动

请求状态、账户账本、全局账本及历史根任务用量在同一存储事务中保存。事务完成后才启动新请求调度。恢复从未决请求重新求和，重复启动不会再次累加占用；结果未知的请求继续使用原身份核对。

## 3. 回归验收

`tests/integration/test_gateway_recovery.py` 覆盖旧 DISPATCH_INTENT 与 UNKNOWN 两种状态。两次连续重启后，原预留与槽位保持一次占用，新请求等待；原请求随后核对完成，消费结算一次，无法支付的新请求明确结束。完整工程检查及隔离验收通过后发布修复。
