# 本轮修改方案

## 1. 结构与页面叙事

第一章以文献、报道和开源 Harness 问题单形成需求，展示问题、需求和目标的对应关系。第二章依次阐述概要设计、工作对象与资源模型、系统架构、运行闭环和接入部署。第三章按 L1—L4 展开，其中银行家检查归入 L2 的等待与死锁控制，明确由 L2 声明阶段、L1 实施资源安全检查。第四章呈现界面原型、对照实验、指标和团队实施计划。

普通内容页采用“核心说明—分组展开—综合结论”。章节导航使用间隔号或分隔竖线；章节过渡页用两句文字说明本章目标与设计产出，不增加大框。九张图按主题进入正文，配具体阅读说明，参考文献单独列于末尾。

## 2. 统一规则

需求与假设按 R1/H1 工具资源、R2/H2 任务与恢复、R3/H3 请求公平、R4/H4 平台协作对应。动态反馈组命名 B11+FB，首次讲研究目标时使用中文对照名称，实验表同时列中文组名。参考文献保留说明书 S01—S23 编号及组合来源，逐页按实际内容引用。

系统模型页解释四种粒度的划分依据，展示 Task、AgentExecution、Step、Attempt 的归属关系及重试关系。工具容量示例统一为总预算 8 GiB、当前剩余 4 GiB。银行家情形写为“给阶段 A”“给阶段 B”，子 Agent 使用编号 1、2。
