# TaskLoom 开题 PPT 修改计划

**版本** v1.0 · **日期** 2026-10-21 · **目标交付** `TaskLoom_开题报告_答辩修订版_v2.0.pptx` 与同版 PDF。

本轮依次完成证据选材、页序与视觉设计、图集和截图更新、PPT 制作及校验。依据为当前主分支、正式方案、上一轮 24 项校对清单，以及本轮新增的三层调研与算法表达要求。

## 1. 修改目标

1. **调研分层。** 学术论文回答机制与理论依据；GitHub Issues 回答特定工程路径的问题；工程报道与经验分析回答开发者观察和系统实践。各层展示原文页面与具体内容，再用两页归纳研究切口及需求。
2. **机制可演示。** 为每个机制选择能直接展示状态变化、资源占用或算法计算的表现形式，正文讲清条件、决策和作用，讲稿补充复杂度与边界。
3. **资料同步。** 架构、部署、对象、请求和取消图与现行系统一致；替换旧静态原型，使用当前代码版本的真实界面与执行记录。
4. **版本可追溯。** 旧件最小归档，新件使用版本后缀；固定名称 `AGENTS.md` 导航至带版本的完整规范。

## 2. 内容与表现形式

| 模块 | 主要内容 | 主要视觉形式 |
|---|---|---|
| 论文研读 | TraceLab、PeakBench、HiveMind；题名、作者/年份、原始图表及适用启示。 | 原文页面、原图/原表、选定数据与局部标注。 |
| 工程问题 | OpenClaw 资源压力与控制请求案例；Codex 特定退出路径；条件与已有覆盖。 | GitHub 原页面快照、关键段落与责任链。 |
| 报道分析 | Anthropic 多 Agent 工程实践、Cursor 长时间自主编码实践。 | 原始报道快照、实践观察、与本项目的联系。 |
| 综合归纳 | 三层证据共同支持什么；转换成哪些需求和待检验目标。 | 证据—问题—机制—验收矩阵及需求映射。 |
| L1 准入 | 可行候选、大工具等待、资源向量与原子预留。 | 甘特图、向量不等式、短伪代码。 |
| 共享访问与 L2 | 初始化合并、锁、动态依赖、等待释放。 | 并发时间线、single-flight 时序、DAG 与资源轨迹。 |
| 阶段银行家 | Need、Work、安全序列、动态 Max 与提交。 | 数值逐步推演、伪代码、状态前后对照。 |
| 生命周期 | 执行、结果、静止、结算；取消与恢复。 | 正交状态图、泳道图、进程与信号时序。 |
| L3/L4 | 成本 DRR、轮转与 hybrid 候选、两级约束。 | 信用账本、轮次推演、槽位时间线与计量对比。 |
| 反馈 | 基础背压、相关压力、有效期与平滑。 | 事件驱动的窗口变化示意及反馈环。 |
| 验证交付 | 三类对照、五组消融、四种容量条件、校准与六工作包。 | 对照矩阵、实验变量、数据来源链、阶段时间线。 |

算法手工例子标为“机制推演”；原文数据注明论文来源；程序截图注明版本和默认模拟模型池。引用采用普通数字 `[1]`，标题/年份在页内可见，完整链接进入备注与参考页。

## 3. 计划页序

| 页 | 内容 | 表现形式 |
|---|---|---|
| 1—5 | 封面、总览、第一章、使用场景、三层调研路径。 | 保留主题与动效；场景、证据层级。 |
| 6—8 | 三篇论文研读。 | 题名/作者/年份、原文页面、原图表。 |
| 9—10 | 工程问题案例。 | GitHub 页面快照与触发条件。 |
| 11—12 | 工程报道分析。 | Anthropic、Cursor 原页面与实践观察。 |
| 13—14 | 调研综合、需求与验证目标。 | 两页证据综合和映射。 |
| 15 | 自研定位与 OpenClaw 三种角色。 | 路线与对照关系。 |
| 16—22 | 第二章、概要、对象、架构、部署、请求时序、实际工作流。 | 更新后的原生可编辑图、当前闭环。 |
| 23—35 | 第三章与 OS 机制。 | 甘特、向量、伪代码、DAG、安全序列、状态机、泳道、信用和反馈示意。 |
| 36—44 | 第四章、界面、监控、对照、指标、仿真、计划、结束。 | 当前截图、实验变量、六工作包。 |
| 45—48 | 分组参考来源。 | 普通数字编号与可点击链接。 |
| 49—52 | 类图、生命周期细图、安全检查与复杂度/边界备查。 | 便于问答的技术细节。 |

完整稿按约 52 页组织，含章节页、4 页参考与4页备查。制作中依据素材可读性小幅调整页序，主讲时按汇报时长选择内容。

## 4. 素材与图集更新

- **论文证据：**沿用已归档的正文，核对题名、作者、图表位置和数据；优先采用原图表或原页面局部，不重绘实验数据。
- **网页快照：**截取原始 GitHub/报道页面，记录 URL、日期与快照范围；保留足够上下文。
- **程序界面：**使用当前主分支的隔离演示实例，或同版本已留存的验收截图；清楚记录时间和版本。
- **图集：**生成带版本后缀的可编辑 draw.io 多页图集，并在 PPT 保持对应的原生可编辑结构；更新统一账号、固定模型池、实际进程、账本与未知结果路径。

## 5. 制作与验收

先完成内容和素材清单，再统一制作；选取论文证据、甘特推演、部署图和当前界面作为代表页检查。完整稿进行一次内容与视觉复核，修正后重新导出受影响页面。

验收检查：三层证据清楚；两页综合形成推理链；算法视觉类别与内容匹配；24项校对得到处置；版本/状态/单位一致；正文和讲稿一致；引用可追溯；无图文裁切和文字溢出；保留可编辑内容及原有主题、装饰和切换效果。
